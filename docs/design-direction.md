# Направление интерфейса CCL2

Этот документ фиксирует визуальное направление, но не является реализацией экранов. Компоненты и макеты появятся на следующем согласованном этапе.

## Основа

- композиция, типографический характер и шрифтовые пары берутся из проекта `site`;
- расположение полезных данных и набор вкладок старого `ccl` используются как UX-референс, а не как техническая основа;
- основной характер — тёмный редакционный fantasy-интерфейс с холодными синими акцентами;
- цвет не является единственным способом передать состояние: ошибки, выбор и недоступность получают иконку или текстовую метку.

## Шрифты

| Назначение | EN | RU |
|---|---|---|
| Заголовки | Forum | Cormorant Garamond |
| Основной текст | Alegreya | Literata |

Для чисел характеристик и табличных значений включаются табличные цифры. Интерфейс должен сохранять читаемость при системном увеличении текста до 200%.

## Синяя шкала

Базовая шкала перенесена из согласованной палитры:

```text
#e9eef5  #ccd8e9  #b0c2dd  #93add1  #7797c4  #5a81b8
#466da3  #3a5a87  #2e476a  #21344d  #152131
```

Роли будут назначаться семантическими токенами (`surface`, `text`, `primary`, `border`, `focus`), поэтому конкретный компонент не привязывается к hex-коду. Красная, жёлтая и зелёная шкалы остаются только для ошибок, предупреждений и успешных состояний.

## Mobile first

- один и тот же функциональный сценарий доступен на телефоне и десктопе;
- основной макет начинается с ширины 320 px;
- цель нажатия — не меньше 44×44 px;
- вкладки конструктора на узком экране превращаются в доступную пошаговую навигацию с сохранением черновика;
- drag-and-drop карточек бросков получает равноценное управление касанием: выбрать карточку, затем характеристику;
- таблицы контента преобразуются в карточки или получают контролируемый горизонтальный скролл без прокрутки всей страницы;
- критические действия требуют понятного подтверждения и показывают, какие данные будут сброшены.

## Локализация

Компоненты проектируются под изменение длины строки минимум в два раза. Технический интерфейс получает строки из JSON-словарей, а названия и описания сущностей — из локализаций контент-пакета. Ни один размер компонента не рассчитывается из фиксированной длины русского или английского текста.
