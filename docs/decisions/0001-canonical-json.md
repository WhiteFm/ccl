# ADR-0001: Канонический JSON

## Статус

Принято.

## Решение

Единым контрактом между Кузницей, Excel, MongoDB, сайтом персонажей и будущим VTT является версионированный JSON, проверяемый JSON Schema.

## Причины

- Excel удобен для массовой редакторской работы, но плохо выражает вложенные зависимости;
- Кузница должна создавать весь официальный контент без Excel;
- VTT и сайт должны одинаково понимать эффекты;
- переносимые файлы не должны содержать исполняемый JavaScript;
- стабильные ID позволяют локализовать данные без влияния на механику.

## Последствия

- Excel импортируется и экспортируется через адаптер;
- Кузница редактирует тот же JSON через формы;
- изменения схемы требуют версии и миграции;
- все приложения используют один пакет типов и валидаторов.
